- [x] 对比主流对话 AI 的通用架构：编排、上下文管理、记忆、工具调用、输出校验、评测观测

## 二、设计原则

- [x] 采用渐进式改造，不进行一次性重写
- [x] 保留现有人设、关系轴、时间感知、图片识别和游戏功能
- [x] 优先解决上下文选择和记忆质量，再扩展工具编排
- [x] 所有行为改动都配套单元测试、对话评测和可回滚开关
- [x] 不让用户输入、网页内容或临时状态绕过系统级规则
- [x] 不要求模型输出完整思维链；内部状态仅保留简短、可控的标签或摘要

## 七、剧情经历记忆专项（M2 子计划）

目标：让彰人能够把剧情、地图对话和共同事件当作“已经发生过的自己的经历”，自然接住群友的具体回忆，同时不凭空补写未覆盖的剧情。

### 7.1 语料补全与事件化

- [x] 盘点当前可用来源：`akito_scripts.json` 共 2502 条，纳入 836 条彰人/冬弥相关候选记录
- [x] 将候选按 `cn_key + category` 聚类为 824 个事件单元，而不是只保存孤立语气示例
- [x] 为每个事件建立稳定 `event_id`、分类、参与者、摘要、主题、置信度和原始证据
- [x] 为彰人与冬弥共同事件保留关系分类标签，并按高/中/低置信度分层
- [x] 为事件保留中文摘要、人物别名、主题关键词和原始台词证据
- [x] 生成前执行证据完整性校验，禁止把模型推测写入事件事实

### 7.2 事件检索与上下文展开

- [x] 建立事件级索引，同时保留台词级/情境级原始证据
- [x] 建立关键词/主题/证据词法召回和可选向量粗召回 + 重排序架构；索引或 rerank 不可用时安全回退 Lexical
- [ ] 补强人物实体、地点和活动标签权重；人工剧情形成首批系统性覆盖后构建生产事件索引并完成 Lexical/Hybrid 对照
- [ ] 查询命中某一台词后，自动展开同一事件的前后文、参与者和关键结果
- [ ] 对“那次、后来、你还记得吗”等指代，优先使用当前会话的活动事件槽和最近事件
- [x] 对多个候选事件保留置信度；线上首阶段只注入高置信度事件，低置信度不进入 Prompt
- [x] 为事件检索建立独立安全评测集与 Recall@1/3、MRR、负例误认率、模糊问法拒绝率指标；原有 12 条仅作为剧情回归种子，不代表完整覆盖

- [x] 召回器增加事件线索、最低分数和弱候选分差门槛；无充分证据时返回 `no_hit`，不向 Prompt 注入事件

### 7.3 角色视角内化

- [x] 为高置信度事件生成带原始证据引用的只读“彰人视角记忆卡”
- [x] Prompt 明确区分客观剧情事实、角色反应参考、当前群友说法和不确定部分

- [x] 要求模型用当前角色语气转述，不机械复述原台词，也不把历史状态当成当前事实
- [x] 运行时保留中文证据与日文原文对照；口吻示例仅在有证据引用时注入，且明确不新增事实
- [ ] 群友确认某个事件后，将 `event_id` 写入短期会话主题，不把它误写成新的长期事实

- [ ] 同一剧情可同时作为事实证据与彰人口吻参考；只在逐字内容重复时合并展示，不互相排除召回或删除任一语义用途
