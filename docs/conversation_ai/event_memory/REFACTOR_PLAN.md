# 剧情事件记忆重构计划

> 目标：让彰人在群友提到具体剧情经历时，能够回忆起“当时发生了什么、冬弥怎么反应、自己说了什么”，再以当前彰人的口吻自然复述。原始剧情是事实证据，模型只负责在证据范围内组织表达。
>
> 更新规则：每完成一个可验证的里程碑就勾选对应项，并记录日期、验证命令和已知限制。未经审核的候选内容不进入线上事件记忆库。

## 1. 数据职责

- [x] `data/content/akito_scripts.json` 继续作为彰人口吻、措辞和反应方式参考，不承担完整剧情事实。
- [x] `data/event_memory/story_import/drafts/` 保存可审核的完整剧情快照：日文原文、地区翻译、动作顺序、说话者和目标片段索引。
- [x] `data/content/akito_event_memories.json` 保存经过审核的“共同经历单元”摘要，供运行时只读召回。
- [x] 页面标题不作为事件事实、时间节点或剧情摘要来源；旧 `title` 字段仅作兼容性索引，运行时不得依赖它生成事实。
- [x] 外部 Wiki/资源站只作为导入源；bot 运行时使用本地快照，避免网络延迟、限流、版本漂移和服务不可用。

## 2. 剧情导入契约

- [x] 活动、组别、卡面、区域、自我介绍和特殊剧情统一解析为 `StoryRoute`。
- [x] 卡面 ID 优先从日服主数据定位，再读取日文 scenario 和可用的中文翻译；URL 中的 `zh-cn` 只表示页面语言。
- [x] 活动等非卡面剧情在目标地区缺失时回退到日服主数据和日服 scenario，翻译仍按页面地区尝试读取。
- [x] 草稿保留完整有序 `actions`，每条记录包含说话者、日文、中文和 `kind`（对白/内心/旁白）。
- [x] `target_segments` 只筛选彰人/冬弥相关片段，避免把心羽、杏等其他角色的整段台词作为目标记忆。
- [x] 对长剧情按“一个场景中的一次互动”拆成多个候选单元，而不是把整章压成一条摘要。
- [x] 每个候选单元至少包含：情景与冬弥行为、彰人关键回应、双方可追溯的动作索引；缺少一方时标记为待审核，不自动发布。

## 3. EventMemory 兼容格式

- [x] 保留现有事件级字段（`event_id`、`source`、`summary`、`topics`、`confidence`、`evidence` 等），避免影响旧数据读取。
- [x] 一个故事可以有多个 `evidence` 单元；每个单元的 `context` 保存共同情景、冬弥行为和必要背景，`dialogue` 只保存彰人关键回应。
- [x] 事件记忆中的文本使用精简中文；完整双语原文和动作索引留在对应草稿及缓存资产中，通过 `source.draft_id` 和 `record_indices` 追溯。
- [x] 新记录不使用页面标题作为 `summary` 的兜底事实；没有人工/审核摘要时保持待审核，不发布。
- [x] 发布前执行 schema、证据引用、目标说话者和去重校验；同一 scenario 的内容变更必须生成修订快照并显式确认。

- [x] 草稿保留 `source_hash`；发布记录保留内容/证据摘要，内容变更需显式确认并生成本地修订快照。

## 5. 运行时召回

- [x] 事件记忆以只读方式检索，低置信度或模糊问题不注入 Prompt。
- [x] 同一事件命中时展示 2～3 个相关互动单元，而不是固定只取首条证据。
- [x] Prompt 明确区分已审核原作事实、未复核脚本候选和彰人表达参考；模型可改写，不要求逐字复述。
- [ ] 群友确认某段经历后，只把 `event_id`/事件主题写入短期会话状态，不自动生成新的长期事实。
- [ ] 用户提出资料未覆盖的细节时，保留“不确定/待核对”状态，不用模型猜测覆盖原作事实。
- [ ] 同一剧情允许同时承担事实证据和语气参考；如线上观察到逐字重复，只合并重复文本的展示，不移除任一用途或互相抑制召回。

## 6. 评测与发布

- [ ] 为每个共同经历单元生成正例、相邻场景例和事实不符负例；评测基线使用相近场景原文作为“态度/思路”参照，不做逐字匹配。
- [x] 检查主动对话、自动回复、群印象三种 surface 是否共享同一事件召回结果，同时保留各自触发和输出约束。
- [x] 先完成离线评测和本地草稿审核，再用 `combined` 群灰度观察；稀疏线上 trace 不阻塞开发，只暂缓扩大放量。
- [ ] 每次批量迁移后重建索引、运行回归测试，并在本文件记录覆盖数量、召回指标和已知缺口。
