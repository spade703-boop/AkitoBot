# 对话 AI 架构升级计划

> 状态：M0 第一阶段与跨表面评测扩展已落地；线上回放待完成
>
> 更新规则：每完成一个可验证的里程碑，就同步勾选本文件；未通过测试或评测的事项不勾选。

## 一、当前进度

- [x] 梳理现有对话链路：输入采集、状态判断、上下文组装、模型调度、输出解析、记忆提交
- [x] 梳理现有能力：短期历史、长期事实、临时状态、语义检索、重排序、联网搜索、视觉识别、结构化输出
- [x] 对比主流对话 AI 的通用架构：编排、上下文管理、记忆、工具调用、输出校验、评测观测
- [x] 确认剧情经历记忆需求：把彰人与冬弥的共同剧情作为可检索、可追溯的第一人称事件记忆
- [x] 形成渐进式升级方案，确定不更换模型、不破坏现有人设与既有功能
- [x] 将计划落盘到本文件
- [x] 用户确认方案与实施边界

## 二、设计原则

- [ ] 采用渐进式改造，不进行一次性重写
- [ ] 保留现有人设、关系轴、时间感知、图片识别和游戏功能
- [ ] 优先解决上下文选择和记忆质量，再扩展工具编排
- [ ] 所有行为改动都配套单元测试、对话评测和可回滚开关
- [ ] 不让用户输入、网页内容或临时状态绕过系统级规则
- [ ] 不要求模型输出完整思维链；内部状态仅保留简短、可控的标签或摘要

## 三、里程碑 M0：基线与数据契约

目标：不改变现有行为，建立可比较的质量基线。

- [x] 定义统一的 `Turn`、`ConversationState`、`ContextBlock`、`ToolResult`、`ResponseEnvelope` 数据契约
- [x] 整理 50～100 条评测样例，覆盖闲聊、追问、群聊转述、冬弥互动、剧情事件回忆（至少 10 条彰人/冬弥共同经历）、时间间隔、图片、搜索、记忆和异常输出；剧情样例绑定原作场景证据、评价量表、期望信号和禁止漂移项
- [x] 建立“原作证据 + 结构化角色裁判”的自动评测：不做逐字匹配，单独评估事实归因、关系态度、情绪方向、语气自然度和剧情臆造
- [x] 为每轮请求增加 request id，并记录意图、上下文来源、工具调用、耗时、Token 和重试信息
- [ ] 测量当前版本的 JSON 解析率、重复回复率、搜索成功率、记忆命中率、剧情角色一致性和 p50/p95 延迟
- [x] M0 评测集校验、自动评测器测试和基线报告骨架通过
- [ ] M0 在线回放完成并填入真实运行指标

### 3.1 跨表面共享能力评测专项

目标：让主动对话、自动回复和群印象共享同一套人设、关系事实与剧情检索能力，同时保留各自的触发、静默和输出约束。

- [x] 扩展评测数据契约，增加 `surface` 与 `task` 字段，区分 `main_chat`、`auto_chat`、`impression_analysis` 和 `impression_reply`
- [x] 建立共享能力评测：彰人口吻、彰人/冬弥关系事实、剧情检索与人物归因、情绪方向、自然度和不确定性控制
- [x] 复用原作剧情证据与结构化角色裁判；允许新措辞，不做原文逐字匹配
- [ ] 增加主动对话专属指标：多轮连续性、追问承接、记忆命中和工具结果使用
- [ ] 增加自动回复专属指标：是否应该插嘴、静默决策、只回应当前消息、当前消息锚点和群聊背景越界
- [ ] 增加群印象分阶段指标：中性分析的材料事实 grounding、证据/不确定性边界，以及最终表达的角色一致性、称呼、长度、候选多样性和复用控制
- [x] 为自动回复与群印象接入统一 trace，记录 `surface`、`stage` 和 `context_sources`，支持按表面拆分基线
- [ ] 先完成三类表面的离线回放，再采集线上分面指标；未通过评测前不勾选完成项

## 四、里程碑 M1：上下文编排器

- [x] 增加 `ContextBlock` 元数据归一化、Token 估算和假设选择器；暂不改变实际 Prompt
- [x] 主对话、自动回复和群印象记录 shadow 选择结果，只保留来源、优先级和估算，不写入上下文原文
- [ ] 用线上 trace 对比新旧上下文选择结果，并确认关键关系/剧情信息不会被误裁剪
- [ ] 在灰度开关下切换实际上下文选择策略

- [ ] 新增统一 Context Orchestrator，集中管理所有上下文来源
- [ ] 将上下文分为系统规则、临时状态、当前消息、角色关系、长期记忆、相关历史、群聊背景和工具结果
- [ ] 为上下文块增加优先级、来源、时效和 Token 成本
- [ ] 增加 Token 预算与分层裁剪策略，保证当前消息和系统规则优先
- [ ] 将历史消息逐步恢复为原生 `user/assistant` 结构，兼容读取旧 JSON 历史

- [ ] M1 对话回归测试与 Token 预算测试通过

## 六、里程碑 M3：任务路由与工具编排

目标：让模型根据任务类型选择正确的路径，并可靠使用外部工具。

- [ ] 将意图路由细分为闲聊、角色互动、本地知识、联网事实、图片理解、记忆操作、管理命令和多步任务
- [ ] 为低置信度意图增加本地优先或澄清式降级策略
- [ ] 将联网搜索结果作为带来源的工具消息，不再仅作为普通文本旁白注入
- [ ] 支持最多 2～3 次的有界工具循环，增加参数校验、超时和失败降级
- [ ] 区分角色事实搜索与现实世界事实搜索，避免联网内容改写角色设定
- [ ] 为搜索结果增加“不确定、无结果、过期”状态
- [ ] M3 工具调用成功率、超时降级和提示注入测试通过

## 七、剧情经历记忆专项（M2 子计划）

目标：让彰人能够把剧情、地图对话和共同事件当作“已经发生过的自己的经历”，自然接住群友的具体回忆，同时不凭空补写未覆盖的剧情。

### 7.1 语料补全与事件化

- [ ] 盘点可用来源：主线、活动剧情、卡面剧情、生日剧情、家园/地图对话、语音和已有人工整理资料
- [ ] 将固定长度的台词窗口整理为事件单元，而不是只保存孤立的语气示例
- [ ] 为每个事件建立 `event_id`、来源、章节/活动、时间线、地点、参与者、前因、关键行动、结果和情绪转折
- [ ] 为彰人与冬弥共同事件增加关系标签：并肩、冲突、承诺、照护、练习、演出、日常等
- [ ] 为事件补充中文摘要、人物别名、关键物件、原句关键词和用户常见转述方式
- [ ] 保留每条摘要和事实对应的原始文本片段，禁止把模型推测写成无来源事实

### 7.2 事件检索与上下文展开

- [ ] 建立事件级索引，同时保留台词级索引作为精确证据
- [ ] 使用关键词/别名、人物实体、地点和活动标签做混合召回，再用语义检索和重排序精排
- [ ] 查询命中某一台词后，自动展开同一事件的前后文、参与者和关键结果
- [ ] 对“那次、后来、你还记得吗”等指代，优先使用当前会话的活动事件槽和最近事件
- [ ] 对多个候选事件保留置信度；置信度不足时先用角色口吻澄清，不强行认领具体剧情
- [ ] 为事件检索建立 Recall@K、事件命中率和误认率评测集

### 7.3 角色视角内化

- [ ] 为每个事件生成带证据引用的“彰人视角记忆卡”：发生了什么、冬弥做了什么、彰人当时的态度、事件留下的关系变化
- [ ] Prompt 明确区分：客观剧情事实、彰人的主观感受、当前群友的说法和模型的不确定部分
- [ ] 注入记忆卡时只提供必要摘要与证据片段，不把整篇剧情灌入上下文
- [ ] 要求模型用当前角色语气转述和回应，不机械复述原台词，不把历史一次性地点/状态当成当前事实
- [ ] 群友确认某个事件后，将 `event_id` 写入短期会话主题，不把它误写成新的长期事实
- [ ] 用户提出语料未覆盖的剧情细节时标记为“用户说法”，等待证据或澄清，不直接覆盖官方事件记忆

### 7.4 覆盖度闭环

- [ ] 建立“来源 × 时间线 × 参与者 × 事件类型”的覆盖矩阵
- [ ] 从事件元数据自动生成常见问法、模糊问法和跨语言问法，持续加入检索评测
- [ ] 记录匿名化的未命中问法和用户纠正，进入离线补录队列，不在运行时自动改变事实库
- [ ] 优先补齐彰人/冬弥共同事件，再扩展到 VBS 伙伴和其他角色关系
- [ ] 每次补录后重新生成事件索引、别名表和评测报告
- [ ] 剧情专项的事件命中率、事实归因正确率和自然度评测通过

## 十、完成标准

- [ ] 关键对话场景的事实归因、人物关系和时间连续性不下降
- [ ] 上下文 Token 使用可控，长对话不会无限膨胀
