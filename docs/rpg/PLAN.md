## 固定约束

- 不新增玩法、不改现有数值目标、不改指令名或存储层格式，不引入新的第三方依赖。
- 普通打怪/组队与世界 BOSS 是两条独立业务线：普通装备损坏、普通战绩和战备结算不能影响 BOSS；BOSS 的临时装备、出手机会和奖励也不能回写普通线。
- 看板只保存群级聚合和必要的参与者计数，不保存消息原文、QQ 号明细或用户名展示；仍由超管指令访问。
- 睡眠时段（北京时间 0–6 点）由各指令分别执行拦截：签到、送礼、偷取、打怪、组队、补给和装备强化允许超管测试豁免；`使用` 道具目前不提供超管豁免，查询类指令不写入数据。维护说明不得将其概括为“所有写操作均可豁免”。
- 任何重构都保持现有导入入口和热重载行为，先用测试证明兼容，再考虑性能优化。

## 数据看板口径

| 数据 | 现在能做什么 | 历史限制 |
| --- | --- | --- |
| 战斗、胜率、单人/组队/失败回退、经验/积分 | 从 30 日聚合埋点直接统计 | 旧存档未记录的细分只能标“暂无历史埋点”。 |
| 怪物、精英、事件、掉落、补给 | 从新埋点统计数量、命中和分布 | 不能从旧数据反推真实触发率。 |
| 强化/购买支出 | 记录成功扣款后的次数与净支出 | 上线前的历史净消耗不可回填。 |
| 世界 BOSS | 记录实例级参与、攻击、伤害、击杀/离场和奖励聚合 | 旧存档不能准确反推每只 BOSS 的人均参与/奖励。 |
| 等级分布 | 用当前经验生成“当前快照” | 不伪造历史等级轨迹。 |

## 验收标准

1. `python -m pytest -q tests/features/rpg` 和 `python -m pytest -q` 全部通过，Ruff 无错误。
2. 普通装备损坏、普通战斗结算或普通羁绊变化不会污染世界 BOSS 的临时装备、出手机会、生命和奖励；反向也成立。
3. 新字段缺失时旧 `gift_data.json` 可无损读取，配置热重载失败不会替换当前有效配置。
4. 看板只展示聚合数据；历史缺失指标明确标注不可用，不做估算性回填。
5. 任何成长调参都要先运行 [`GROWTH_BASELINE.md`](GROWTH_BASELINE.md) 中的模拟检查，并记录偏差原因。
